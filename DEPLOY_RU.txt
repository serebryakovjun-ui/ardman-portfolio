ARDMAN — размещение и запуск без внешних зависимостей

В этой сборке удалена обязательная загрузка Telegram SDK с telegram.org.
Карта, шрифты, код, фотографии и данные загружаются с того же сервера, что и сайт.
Ссылки на источники не нужны для запуска страницы. Это не отменяет возможные
ограничения доступа к самому хостингу у конкретного провайдера.

Обновление существующего GitHub Pages:
1. Распакуйте архив в папку ardman-portfolio с заменой файлов.
2. Убедитесь, что catalog.js, catalog.css, smooth.js и smooth.css попали в папку.
3. GitHub Desktop: Commit, затем Push origin.
4. После завершения публикации обновите страницу Ctrl+F5.

Если GitHub Pages не открывается без VPN:
Можно разместить те же файлы в Yandex Cloud Object Storage, без покупки домена.
1. В своём аккаунте Yandex Cloud создайте отдельный бакет для этого сайта.
   Имя должно быть уникальным, без точек (например ardman-portfolio-ваш-суффикс).
2. Разрешите публичное чтение объектов. Не выдавайте публичное право записи.
3. Загрузите распакованное содержимое, сохранив вложенные папки assets.
   index.html должен лежать в корне, не внутри дополнительной папки.
4. Включите хостинг статического сайта, главная страница — index.html.
5. Откройте HTTPS-адрес, показанный в консоли, без VPN на Wi-Fi и мобильной сети.
   Для бакета без точек поддерживается https://ИМЯ-БАКЕТА.website.yandexcloud.net
6. Когда проверка пройдёт, отправляйте заказчикам новый адрес. Старые ссылки
   GitHub сами по себе на новый хостинг не перенаправляются.

Размещение здесь не выполнено: необходим доступ к вашему аккаунту хостинга.
Хранение и трафик тарифицируются провайдером; перед созданием проверьте тариф.
Работоспособность без VPN из российских сетей в этой среде не проверялась.

Официальная инструкция:
https://yandex.cloud/ru/docs/storage/operations/hosting/setup
HTTPS:
https://yandex.cloud/ru/docs/storage/operations/hosting/certificate

Прямые ссылки на объекты используют #object/ID, поэтому работают на статическом
хостинге без настройки серверных маршрутов.
